ChaosFilter

A Rust workspace that combines a CLI controller with an eBPF program (via Aya) to inject controlled chaos into Linux systems—such as network impairment (delay/loss) and resource stress controls.

Rust 2024 edition Aya eBPF TOML config

  • chaosfilter-ebpf/ — eBPF program
  • chaosfilter-common/ — shared types

Project overview

What it does

ChaosFilter is built to inject failure conditions in a controlled, repeatable way. It helps you exercise resilience—timeouts, retries, backpressure, and fallbacks—against realistic Linux behavior.

  • Network impairment: delay and packet loss on an interface
  • Config-driven: one TOML file describes a run (“plan”)
  • eBPF under the hood: integrates with the kernel via Aya
How it’s used

The CLI reads a config, validates it, then applies injectors for a scheduled duration. You need a capable Linux host: eBPF, bpftool, traffic control (tc), and enough memlock for maps—see Environment setup below.

Quick help
cargo build
cargo run -- --help

Environment setup (Linux)

ChaosFilter is developed and run on Linux with eBPF, bpftool, and traffic control (tc).

System packages

The build compiles Rust, native code, and eBPF; these packages provide a compiler, kernel headers, bpftool, and networking tools ChaosFilter expects at build and run time. 

sudo apt update
sudo apt upgrade -y

sudo apt install -y \
  build-essential clang llvm libelf-dev zlib1g-dev libclang-dev \
  linux-headers-$(uname -r) pkg-config bpftool iproute2 iptables \
  net-tools curl
Rust + BPF target

The workspace builds the CLI and crates for userspace; the bpfel-unknown-none target is required to compile the eBPF program. 

curl https://sh.rustup.rs -sSf | sh
source $HOME/.cargo/env

rustup target add bpfel-unknown-none

Aya-based tooling sometimes uses cargo-generate for project scaffolding.

Kernel eBPF features

Lists BPF-related capabilities your kernel exposes—useful before debugging load failures.

bpftool feature
cgroup v2

ChaosFilter’s cgroup-related injectors expect a unified hierarchy. If you want to verify that your system is using cgroups v2, run: 

stat -fc %T /sys/fs/cgroup/

You should see cgroup2fs.

memlock

Loading eBPF programs and maps can require raising the locked-memory limit for your shell. For a persistent limit, configure systemd or /etc/security/limits.conf per your distribution. 

ulimit -l unlimited
File descriptor limits (inspect)

The filesystem injector can adjust RLIMIT_NOFILE; to inspect current soft/hard limits for open files on a process: 

cat /proc/<pid>/limits
# or
prlimit --pid <pid>

Usage

Validate a config
cargo build
cargo run -- validate -c, --config <path-to-toml-file>
Run chaos with a config
cargo build
cargo run -- chaos -c, --config chaosfilter.toml

Run cargo run -- init (or chaosfilter init after install) to write a starter config to the current directory.

Example TOML config

The init subcommand emits a commented template; the shape matches the following (abbreviated for the page). 

# ChaosFilter Example Configuration
#
# Usage:
#   chaosfilter chaos --config cf-config.toml
#
# This file defines:
#   - Targets (what to affect)
#   - Schedule (how long to apply chaos)
#   - Injectors (what kind of chaos to apply)

# --------------------------------------------------
# Plan Metadata
# --------------------------------------------------

name = "example-plan"

# --------------------------------------------------
# Schedule
# --------------------------------------------------

[schedule]
# Duration to keep chaos active (seconds)
duration_s = 10

# ==================================================
# Injectors
# ==================================================

# -----------------------------
# Network (tc netem)
# -----------------------------
[injectors.network_config]
enabled = false

# Network interface to target (for example: eth0, enp5s0, vethA)
# Use "default" to resolve the system default interface at load time.
target_iface = "default"

# Network delay in milliseconds
# delay_ms = 100

# Packet loss percentage (0.0 - 100.0)
# loss_percent = 10.0

# Cgroup attach points for network classifier
# Example: [117, 419, 666]
# network_ebpf_cgroup = [24059]

# -----------------------------
# CPU + Memory (cgroup v2)
# -----------------------------
[injectors.memory_config]
enabled = false

# PID to constrain
# target_pid = 12345

# Move PID into target cgroup before applying limits
# move_pid = true

# Controllers to enable in cgroup.subtree_control
# enable = ["cpu", "memory"]

# CPU quota/period
# Example: "20000 100000" = 20% of one CPU
# cpu_max = "20000 100000"

# CPU weight (1 - 10000)
# cpu_weight = 200

# Hard memory limit
# mem_max = "1G"

# Soft memory pressure threshold
# mem_high = "800M"

# Swap limit ("0" disables swap, "max" allows unlimited)
# swap_max = "0"

# -----------------------------
# Block I/O (cgroup v2 io)
# -----------------------------

# Block I/O Injector
[injectors.block_config]
enabled = false

# The target device that the I/O constraints will be applied to.
# device = "/dev/sda"

# Read bandwidth limit (bytes per second).
# rbps = 10485760

# Write bandwidth limit (bytes per second).
# wbpd = 10485760

# -----------------------------
# File Descriptor Exhaustion
# -----------------------------
[injectors.filesystem_config]
enabled = false

# PID whose process context will be targeted
# target_pid = 12345

# New soft RLIMIT_NOFILE value
# soft_limit = 64

# New hard RLIMIT_NOFILE value
# hard_limit = 128
